# 0018 AGY 的版本表依版本取值：認得 1.5.6；內建檔的雜湊認所有已知版本在同一個路徑釘的值（AGY 自己更新後，舊版寫的資料夾不用刪）

日期：2026-11-12　狀態：已決定（v0.25.2「認得 AGY 1.5.6」；使用者要求支援 Gemini（AGY）新版，細節由協調者決定。依據 ADR 0012、`docs/evidence/agy-1.5.3-chat.md`、`docs/evidence/agy-1.5.5-not-added.md`、`docs/evidence/agy-1.5.6-chat.md` 與 `docs/SECURITY-MODEL.md` 的「A new version of AGY (v0.25.2)」）

## 背景

AGY 會自己更新。使用者的 AGY 從 1.5.3 更新到 1.5.5、又到 1.5.6，VBear 只認得 1.5.3，所以 Gemini 員工不能聊天。
v0.22.1 對 1.5.5 的結論是「不加」（ADR 0012 的後續，`docs/evidence/agy-1.5.5-not-added.md`）：只能靜態比對，而內建檔的雜湊要有真的 AGY 寫出資料夾才拿得到，1.5.5 的執行檔後來也已經不在這台 Mac 上。
這次（2026-11-12）用真的 1.5.6 在**沒有登入、沒有送任何 prompt、HOME 是空的暫存資料夾**的條件下，讓它寫出自己的資料夾（`session/new` 那一步就會寫；只送 `initialize` 時還沒有），取得 41 個內建檔的 SHA-256；其餘證據是 `--help`、`acp --help` 與執行檔的字串。
結果：資料夾的 62 個路徑和 1.5.3 完全相同，26 個檔案的內容相同，15 個不同（沒有新增或消失的路徑）。

## 決定

1. **加 `agy_chat_protocol.VERSIONS["1.5.6"]`。** 協定常數（argv、環境變數、settings、模型、選項種類、用量欄位、`announced_kinds`、`home_created` 等）沿用 1.5.3 的，因為真的 1.5.6 的 help、字串與資料夾名稱都和 1.5.3 的證據一致；
   只有 41 個內建檔的 SHA-256 表是 1.5.6 自己的（來自真的 1.5.6 寫出的資料夾）。登入後才看得到的東西（`session/new` 的回答、權限請求與工具呼叫的格式、用量、AGY 執行指令後建的名稱）這次沒有驗到，
   不假裝：它們由使用者在自己的 Mac 按「聊天安全檢查」那一次真的執行來驗，驗不過就不放行。
2. **認得不等於放行。** 版本表只是 VBear 願意在聊天安全檢查通過後啟動它；`agy-chat-verified.json` 本來就依版本記，而且每筆紀錄要指向「同一個版本」的報告，所以 1.5.3 通過的紀錄不會讓 1.5.6 被當成通過（有測試鎖住）。
   AGY 再自己更新到下一版時，VBear 又不認得，要等下一版。
3. **內建檔的表依「要啟動的 AGY 版本」取值。** 檢查聊天資料夾時（`check_chat_home`、`ensure_chat_home`、`home_state`、`write_settings`，以及聊天安全檢查的報告）用的是那個版本的路徑表；沒有表的版本（例如 1.5.5）直接拒絕，什麼也不建立。
   其餘表（settings、不准的名稱、AGY 自己會建的名稱）每個版本都一樣，由測試與守門第 20 條保證；哪天有版本不一樣，要先改成依版本取值才能加。
4. **內建檔的雜湊：任何一個 VBear 認得的版本在「同一個路徑」釘的值都放行。** 路徑仍然要逐字完全符合要啟動那個版本的表；不在任何一張表裡的雜湊照舊拒絕；會被執行的內建檔（`.js`、`.mjs`、`.json`、`.html`…）一樣只認表裡的雜湊，
   沒有任何一張表釘到的一律拒絕，不因為「是舊版的」就略過；一個路徑的雜湊不能拿去放行另一個路徑。
   **為什麼不是「只認目前版本」：** 使用者在 1.5.3 聊過，聊天資料夾裡是 1.5.3 寫的內建檔；AGY 自己更新到 1.5.6 之後，第一次啟動前資料夾還是舊的（AGY 會不會在啟動時重寫它，目前沒有任何觀察能回答）。
   只認目前版本，第一次啟動就會被擋，而 VBear 從不替使用者刪東西，使用者只能自己去刪資料夾，這對一般使用者不可行，每次 AGY 自己更新都會再來一次。
   放行舊版雜湊的理由：那些檔是 AGY 自己發行過、VBear 逐檔釘過的檔，不是別的程式放的；路徑、檔案種類（檔或資料夾）與「可執行檔一定要有釘到的雜湊」的限制全都照舊。
5. **聊天安全檢查的報告記「和哪個版本的表比」**（`observations.builtin_hashes.table_version`），一個檔和這個版本的表不同、但是別的已知版本釘的值時，記在 `other_version`。

## 考慮過的其他選項

- **只認目前版本的雜湊。** 見第 4 點：AGY 自己更新後第一次啟動就被擋，使用者只能手動刪資料夾。不選。
- **偵測到舊版內建檔時由 VBear 刪掉或移走。** VBear 不刪使用者資料夾裡的東西（ADR 0012），也不該替人動 AGY 的對話副本。不選。
- **只比路徑、不比雜湊。** 會放過同名但內容被換掉的可執行檔（內建的 sidecar 是 node 程式）。不選。
- **1.5.6 的表直接用 1.5.3 的（像 1.5.5 當時想的）。** 15 個檔的內容不同，會在第一次啟動就被擋。不選。

## 後果

- 安裝 AGY 1.5.6 的人在「聊天安全檢查」通過後可以聊天；沒有通過、或 AGY 再更新到下一版，仍然不能。
- 殘餘風險：AGY 若不重寫舊版的內建檔，AGY 跑的就是舊版內建檔（和寫它的那一版跑的是同一份）；這是 VBear 對任何已釘過的 AGY 檔的既有假設。
- 殘餘風險（審查 R1 補記）：
  - 因為每個內建檔「只要等於任一已知版本在同一路徑的值」就放行，聊天資料夾可以是新舊兩版的檔案**逐檔混合**；VBear 不要求整個資料夾都是同一版。舊版（1.5.3）也會接受只有新版（1.5.6）才有的檔案內容。
  - 沒有檢查內建檔的硬連結數（`st_nlink`）、擁有者與寫入權限：目前沒有實機證據，怕誤擋，所以先不加。檢查時仍是不跟隨連結地讀檔並比對雜湊；若已有別的使用者可寫的另一個名字指到同一個檔，檢查之後的改動不會被看見。聊天資料夾本身是 0700、這個使用者的。
  - 通過紀錄是依版本記的，沒有綁定當時受檢的執行檔身分（既有的版本相容性模型）。
- 每個新版本仍然要有證據檔、`AGY_SOURCES` 的項目與自己的內建檔表（守門第 20 條）。

## 補記（v0.25.5：認得 AGY 1.5.7）

1.5.7 用同一套做法加進來（證據：`docs/evidence/agy-1.5.7-chat.md`），有一點和 1.5.6 不同：**內建檔的路徑表長了**。真的 1.5.7 寫出的資料夾是 1.5.6 的 62 個路徑，加上一個新的內建技能（資料夾 `skills/mcp-app-development` 和它的 `SKILL.md`），共 64 個路徑、42 個檔。

- **路徑表仍然跟著正在啟動的版本走，不是「任一版本的路徑」。** 1.5.7 的資料夾給 1.5.6 啟動會被擋（那個路徑不在 1.5.6 的表裡，訊息會點名）；1.5.6 寫的資料夾（沒有那個技能）給 1.5.7 啟動是對的，因為表有、資料夾沒有不算錯。若把路徑也改成「任一已知版本有就放行」，一個舊版啟動時就會放過只有新版才有的檔案，不選。
- **雜湊照舊：任一已知版本在同一路徑的值都放行。** 7 個舊檔（`.checksum`、`.manifest`、`swarm_board/hive.css`、`swarm_board/hive.js`、`antigravity_guide/references/app.md`、`native_swarm/SKILL.md`、`swarm_narrator/SKILL.md`）的內容和 1.5.6 不同，另外新檔一個，其餘 34 個和 1.5.6 一樣。`hive.js` 是會被執行的檔，現在在三個版本各有一個值，只有這三個放行。
- **管理員來源清單沿用 1.5.6 的**；字串裡多出三個以 `com.google.antigravity` 開頭的較長名稱（`.companion`、`.dev`、`.insiders`），證據看起來是其他應用程式的識別名稱，來源表一個版本只有一個網域，沒有加，列為待決事項（見證據檔）。
- 守門第 20 條自動涵蓋 1.5.7（來源項目、證據檔、42 個檔各有雜湊、能執行的檔都有雜湊）。
