# 0020 員工知道自己的名字（開新聊天時，伺服器在系統提示最前面加一小段身分說明）

日期：2026-11-12　狀態：已決定（v0.25.3；依據使用者的話「讓員工建立時自動帶名字」，設計由協調者定。細節見 `docs/SECURITY-MODEL.md` 的「An employee knows its own name (v0.25.3)」）

## 背景

使用者的 Codex 員工「阿福CEO」被問「你是誰」時答「我是 Codex，你在 VBear 裡的 AI 助手」。原因：聊天送給 AI 的系統提示只有「卡片自己寫的說明、記憶段、共用資料夾段」，員工的名字與職位一個字都沒送；首頁建立的 CEO 說明（`first_ceo.INSTRUCTIONS`）只說「你是我的 CEO」，沒有名字；卡片沒有自己寫說明時甚至什麼都不送。AI 工具自己的底層設定又是「你是 Codex」，所以照實回答。

「建立時自動帶名字」只能改到新建立的員工的預設說明；已經建好的員工、改名之後、沒寫說明的員工都不會變。

## 決定

1. **每次一對一聊天開新的 session 時，伺服器在系統提示的最前面加一小段身分說明。** 名字與職位取自卡片當下的資料，所以已建好的員工、改名後的新對話、沒寫說明的員工都有效，使用者不用做任何事。
   固定格式，由 VBear 組，不能由使用者自訂：「[VBear 身分] 你在 VBear 裡的名字是「{名字}」，職位是 {職位}。使用者叫這個名字，就是在叫你；被問到你是誰時，請用這個名字介紹自己，也可以說明你是用 {工具} 運作的。名字和職位只是稱呼，不會改變你能做或不能做的事。」
   沒有職位時，職位那段和「職位」兩字都不寫。最後一句講工具名（Claude Code／Codex／AGY），讓它不必說謊。
2. **名字是使用者打的字，會進系統提示，所以先清理。** 壓成一行（控制字元、換行、空白變成一個空格，看不見的格式字元刪掉）、「」換成『』（名字放在「」裡，不能結束引號）、最多 64 字（職位 32 字）；清理後是空的，或含 VBear 的標記，或記憶規則會擋的（金鑰、密碼句、email、卡號）就**整段不送**，員工不知道名字，「員工上線」那行也照實寫「沒有帶名字和職位」。
3. **職位只用卡片職位的顯示標籤**（`POSITION_TABLE` 的 label，例如 planner 是 CEO），沒有職位就沒有那一段。沒有自訂職位這種東西。
4. **伺服器組欄位、daemon 重組句子。** `chat_service` 把清理過的 `{name, position}` 放進 `chat_send` 的新欄位 `identity`；daemon 用同一組函式（`memory_rules.prepare_identity`）檢查並組出句子，欄位不是清理過的封閉形狀就 `bad_request`、什麼都不啟動。daemon 不讀卡片；工具名由聊天的引擎決定，不由呼叫者決定。（計畫原本寫「伺服器組好整段字串傳給 daemon」；改成傳兩個詞、由 daemon 組句，這樣句子的格式只在 daemon 與伺服器共用的一處，呼叫者無法塞進自己的句子。）
5. **三種引擎都接在同一個 `memory_rules.combine` 的最前面：** Claude Code 的 `--append-system-prompt`、Codex 的 `developerInstructions`（`thread/start` 與 `thread/resume`）、AGY 的 `session/new`／`session/resume` 的 `systemPrompt.append`。AGY 既有的作法就是這個欄位（卡片說明、記憶、共用資料夾已經走這裡），沒有新的協定。
6. **聊天附加提示的上限從 9,000 字放寬到 9,500 字**（`agent_sessions.MAX_CHAT_APPEND_PROMPT`），身分段最多 400 字，否則卡片說明、記憶、共用資料夾都放滿時會放不下。完整模式出發的 2,000 字不動。
7. **「設定改了」提示（P42-6）的指紋。** `prompt_sha` 只有在有身分段時才把它併進去（掛在共用資料夾段後面、有自己的標籤），沒有身分段時值和 v0.25.2 一樣。`chat-prompt/<id>.json` 只有在 session 開始時帶了身分段才多一個 `identity: true`。比較時：檔案有這個鍵 → 用現在的名字與職位重算（名字或職位改了、或現在已經沒有可送的名字，就是「改了」）；沒有這個鍵（升級前開的對話、或開始時沒有可送的名字）→ 照舊方式比，名字不算。所以升級不會把舊對話全標成「改了」。提示的字加了「名字、職位」。
8. **「員工上線」那行**多說「帶著名字和職位」或「沒有帶名字和職位」，依據是 `process_started` 紀錄新增的選填布林 `identity`（daemon 寫的事實）；舊紀錄沒有這個欄位，那行就不提。
9. **舊對話接著聊（resume）時，Claude Code 沿用舊的系統提示**，所以舊對話裡的員工還是不知道名字；只有開新對話才生效，CHANGELOG 與提示都這樣寫。Codex、AGY 的 resume 是否套用新提示沒有驗證過，同樣只承諾新對話。
10. **資料流向：** 名字與職位和對話內容一樣送到這位員工用的那家公司（Anthropic、OpenAI 或 Google）。聊天頁頁首「對話會送到 {公司}」不用改。

## 沒有改的

- 卡片本身：身分段不寫進卡片的說明，使用者自己寫的說明、記憶、共用資料夾照舊送，順序在身分段後面。`first_ceo.INSTRUCTIONS` 不用改（它自稱「你是我的 CEO」，與身分段一致，沒有別的名字）。
- 群組聊天、例行工作、派工步驟走同一個 `ChatService._send`，所以也有身分段；會議（`meetings.build_prompt`）、幕僚長、終端機的「貼上職位指示」是另外的路，這版沒碰（會議的主席會在資料裡看到各發言者的名稱與職位，但發言者本人不會被告知自己的名字；終端機貼上的只有卡片的說明）。
- 沒有新增 API 路徑、設定鍵、聊天事件種類、`localStorage` 鍵；聊天安全檢查（`chat_check` 等）不送名字，沒有改。

## 考慮過的其他選項

- **只改首頁建立 CEO 的預設說明**（把名字寫進去）：已建好的員工（包括出問題的阿福CEO）不會好，改名不跟著變，沒寫說明的員工沒有。不選。
- **讓使用者自己寫身分段**：名字以外的字會進系統提示，等於多一條不受格式約束的送出路徑。不選。
- **把身分句併進卡片的 instructions 再存回卡片**：改了卡片的內容（使用者看到自己沒寫的字），改名要同步，指紋和「卡片自己的指示」的意思都被攪混。不選。
- **record 不加欄位，改從 `chat-prompt` 檔推斷「員工上線」那行**：舊版讀得懂新紀錄（降版安全），但一個聊天可能有好幾次「新」的 process，那行會對較早的幾次說不準。選了計畫的作法（紀錄寫事實），代價是 v0.25.2 讀不懂 v0.25.3 開的聊天紀錄（見 CHANGELOG 的降版說明）。

## 後果

- 被問「你是誰」時，員工在新對話裡用自己的名字介紹自己；對話的內容沒有因此被改寫，名字和職位只是稱呼。
- 名字多了一條送到 AI 公司的路（和對話同一家）。名字清理與不送的條件寫在上面；「像命令的名字」仍會送，因為它在引號裡、一行、且前面已說明那只是稱呼。
- 沒有在真的電腦上用真的工具試過（測試用假的 Claude Code、Codex、AGY）；真的模型是否照名字回答沒有驗證。

## 守門規則 22（寫成測試，規則 1–21 一條沒放寬；15b 的聊天紀錄形狀只多承認 `process_started.identity` 這一個欄位）

- **22a 身分段一定在系統提示最前面**（`tests/test_autonomy_guard.py` 的 `EmployeeNameRules`）：`memory_rules.combine` 的清單第一個是身分段；`daemon_chat.py` 裡每一個 `combine` 呼叫（三種引擎）都把它放在第四個參數。壞樣本：放最後、放第二、`combine` 不收它、daemon 漏傳、用關鍵字傳、傳別的值、只剩兩種引擎。
- **22b 名字一定經過清理函式**（同上）：`ChatService._identity` 只回 `memory_rules.identity_parts(...)` 或 None；`identity` 欄位只被它的結果設定；daemon 讀 `req["identity"]` 只為了交給 `prepare_identity`；`identity_block` 用 `identity_parts` 核對。壞樣本：用原始名字、從卡片直接設、daemon 直接用原文或在別處讀、組句不核對。
- **22c 身分段的格式是固定字串**（同上）：`identity_block` 只用 `IDENTITY_*` 常數與它們的 `.format`，沒有 f-string、`%`、其他字串相加、`join`／`replace`，常數只有 `name`、`position`、`tool`、`label` 四個欄位。壞樣本：f-string、`%`、自己的句子、多出的欄位、對使用者的字呼叫 `.format`、`join`、常數是算出來的、常數不見。
- 行為測試在 `tests/test_p58_identity.py`（清理、句子、指紋與舊對話、三種引擎各接在哪、daemon 拒絕壞欄位、console 送什麼、「改了」的提示），前端在 `tests/frontend/p58_chat.cjs`。
