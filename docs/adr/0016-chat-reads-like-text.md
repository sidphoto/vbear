# 0016 聊天頁像在讀文章：員工的話沒有框，工作紀錄收成一行，輸入框和首頁一樣、可以換員工（修正 ADR 0013 的第 6 點）

日期：2026-11-12　狀態：已決定（使用者 2026-11-12 要求「讓整體使用流程更順利上手，介面優化更接近極簡對話風格」；設計由協調者決定（依「介面改版由我主導」）；v0.24.0「極簡對話 2」做完後定稿。細節依 ADR 0001、0003、0013、0015、GLOSSARY 與 `docs/SECURITY-MODEL.md` 的「Chat reads like text (v0.24)」）

## 背景

v0.23.0（ADR 0015）把首頁變成一句問候和一個輸入框，但聊天頁還是 v0.21 的樣子：員工的每則回覆、你說的每句話、每一次用工具、每一回合的結算，各是一個有框、有底色、有陰影的盒子；
一段短短的對話，畫面上有幾十個盒子，真正的內容（員工說了什麼）被框和小字夾在中間，要用的人自己從框裡挑出來讀。頁首有大標題、狀態、一行說明、「詳細資訊」、「⋯」，輸入框和首頁的框長得不一樣，
想換一位員工說話要先回到員工頁。使用者希望更接近極簡對話介面：字多、框少。

## 決定

1. **對話內容：字多、框少**（**修正 ADR 0013 第 6 點「聊天頁只剩對話」的畫面細節**：訊息按鈕滑過或聚焦才出現、輸入框固定在底部、「⋯」裡的項目與確認框都照舊）。
   - 員工說的（`reply`、正在寫的 `partial`、`thinking`）沒有框、沒有底色、沒有陰影，靠左，行寬照欄寬，上面一行小字只寫名字。你說的（`user`）靠右，一個中性淡底（`--panel-2`）的圓角泡泡，沒有框線。
   - 時間留在頁面裡（`.chat-time`，螢幕閱讀器讀得到），滑過、鍵盤聚焦時顯示，沒有滑鼠的裝置一直顯示。VBear 依分配工作送出的那則話，上面一行（說明不是你打的）一直顯示。
   - 內容欄置中、最寬 720px；準備頁、對話紀錄清單頁也是同一個欄寬。
2. **工作紀錄收成一行，而且只是顯示。**
   - 連續出現的「用了工具」（`tool`）、「工具回的結果」（`result`）、「VBear 自己允許」（`auto`）、「回合結算」（`cost`）、「員工上線」（`process`）、「程序結束」（`process-end`）收成一個預設收起的 `<details data-chat="quiet-group">`。
     摘要那一行照實數、只列真的有的種類（例如「員工上線 1 次・用了 3 次工具・工具回了 3 筆結果・自動允許 1 次・細節」；有結果失敗時寫「（1 筆失敗）」）。**摘要行沒有金額**（ADR 0013 第 5 點）；打開才看得到原本的每一行，每回合的金額與「估計、不是帳單」都還在裡面。
   - **永遠直接看得到、不得收進任何摺疊：** 要你決定的卡片（`card`、即時的 `live-card`，後者是整頁唯一有框的東西）、決定紀錄（`decision`）、被拒絕（`denied`）、錯誤（`error`）、不認得的訊息（`anomaly`）、你說的與員工說的。
     另外，兩種「看起來是結算、其實不是正常做完」的紀錄也留在外面：被你停止、超時、碰到上限、出了問題的回合（`turn_ended` 的原因不是「做完了」），以及程序因為這版畫面不認得的原因結束（例如「交人工處理」）；它們照舊寫出原因。
   - **摺疊是純顯示：** 不因為摺疊少畫、延後畫或丟掉任何一筆紀錄；每一行仍是頁面上原本的元素，帶著自己的 `data-seq` 與 `data-chat`。新的紀錄進來時接在最後一個還開著的摺疊裡，只重寫那一行摘要，不重畫摺疊本身，所以你已經打開的不會被關掉。
3. **輸入框和首頁是同一個**（共用 v0.23.0 的 `.home-box`、`.home-box-bar`、`.home-send`、`.home-example`）：文字區在上，右下是送出，「停止這一回合」在送出旁邊，仍固定在可視範圍底部。**Cmd/Ctrl + Enter 送出、Enter 單按換行**；輸入法組字中的 Enter 不送。
   送出、停止、上限、不能送的原因的邏輯全部不變，只搬位置。CEO 的兩個開場選項改成首頁範例句同樣的小膠囊，行為不變（只放字）。
4. **在輸入框裡換員工說話**（左下角的小鈕 `data-ask="who"`，首頁和一對一聊天頁都有；群組與定時工作的對話沒有）。
   - 清單只用手上已有的資料：首頁用它已讀到的 `GET /api/chats`，聊天頁用進來時已讀的那一次；**打開清單、選取都不再發任何請求**；資料沒有就不顯示這顆鈕。
   - 現在能聊的員工是選項（目前這位標「目前」），還不能聊的列在下面、灰色、寫一句白話原因（用 `chatPrepState` 與 `plainWords`），按了是去那位員工的準備頁（輸入框裡的字跟著放在那位員工底下），不是選取。不預選誰、不依狀態重排、不自動按任何確認。
   - **首頁：** 選了誰，送出就送給誰，走和送給 CEO 同一條路（`openChatWith(那位的 id, { text })`）；選取本身只改「這個框是對誰說的」，不發請求；重新整理回到 CEO，不記在任何地方。
   - **聊天頁：** 選了別人 = 到那位員工最近的一個對話頁（已讀到的聊天清單裡有的話），沒有的話到開對話的準備頁（開對話由那裡的按鈕做）；輸入框裡還沒送出的字放進 `ceoDrafts` 帶過去，在那一頁的輸入框裡，**只有那一頁的送出鈕會送**。**選取本身不送出任何訊息、不發任何寫入請求、不再讀聊天清單。**
5. **頁首縮成一行：** 名字（`h1`，字級縮小）、狀態小標、「⋯」。那行「職位・AI 工具・每件事先問你・對話會送到哪一家公司」**保留**（它是資料流向與權限的說明，不是裝飾），只是字小一級、灰色；「詳細資訊」照舊。
   對話紀錄清單頁改成一列一列（名字、最後時間、有事等你的小點），不用卡片框；內容與連結不變（原本的「等你回覆卡片」字樣、回合數、最後一句都還在）。
6. **只改畫面。** 不改 `vbear/` 的任何伺服器、聊天、啟動邊界、花費程式（版本號那一行除外）；不新增 API 路徑、請求種類、設定鍵、資料檔、聊天事件種類或瀏覽器 `localStorage` 鍵；守門規則 15b 照舊通過；每回合上限、每天上限、定時工作上限、權限卡片與警語一個都沒動。

## 考慮過的其他選項

- **把所有工作紀錄（連同「問你」的卡片、被拒絕的、錯誤）都收進摺疊：** 最乾淨，但會把要你決定或該注意的事藏起來；這些永遠直接看得到（寫成守門規則 18a）。
- **把被停止、碰到上限的回合也收進去（`cost` 一律收）：** 這幾種寫的是「這回合沒有正常做完、為什麼」，等於一種異常；留在外面，只有做完的回合收起來。
- **摘要行寫金額：** 違反 ADR 0013 第 5 點（金額收起來）；金額在打開之後每一行裡。
- **選了員工就直接開（或建立）那位的對話：** 建立對話是寫入；選取不該有任何寫入，所以沒有對話時停在準備頁，由那裡的按鈕開。
- **選了員工，輸入框的字留在這一頁、下次送出才改送給那位：** 聊天頁的輸入框屬於這個對話；換人就換頁，字跟著去，比「同一個框送給不同人」不容易送錯。
- **記住首頁上次選的員工：** 要新的瀏覽器鍵或伺服器欄位；重新整理回到 CEO 就夠。
- **Enter 單按送出：** 誤送會直接花錢；維持 Cmd/Ctrl + Enter（ADR 0013、15c、17c）。

## 後果

- 一段對話在畫面上主要是字：你說的泡泡、員工說的文章、中間一行「用了幾次工具」；要看細節點開，要決定的事在原處。
- 摺疊在 DOM 裡是 `<li data-chat="quiet-item"><details data-chat="quiet-group">`，裡面的 `<ul data-chat="quiet-list">` 放原本的那些 `<li>`；測試與工具找 `data-chat="tool"` 等屬性仍找得到，只是現在在摺疊裡面。
- 聊天頁的輸入框多了一個「輸入法組字中的 Enter 不送」的條件（首頁原本就有）；只更嚴，不會多送。
- 清單打開時還沒讀到聊天清單（頁面進來時那一次失敗）就沒有這顆鈕，不是壞掉；重新整理後有。已知限制。
- 守門規則 18（18a–18d）把這些寫成測試，見下。
- 回到 v0.23.0：沒有資料要轉換，沒有新的設定鍵或瀏覽器鍵。

## 守門規則 18（寫成測試，規則 1–17 一條沒放寬；15b 不改、照舊通過）

- **18a 摺疊只收工作紀錄**（`tests/test_autonomy_guard.py`，加 `tests/frontend/p51_chat.cjs`）：`chatIsQuiet` 只對 `tool_call`、`tool_result`、`auto_allowed`、`process_started`、`turn_ended`、`process_ended` 說可以；
  `card`、`card_decision`、`denied`、`error`、`anomaly`、`user_message`、`reply` 永遠不在摺疊裡；`chatQuietLog` 把其他每一行直接接在清單上、把每一行放進摺疊一次，不丟、不移除任何一行。
- **18b 換員工不送出、不寫入**（同一個檔，加 `tests/frontend/p51_who.cjs`）：換員工的處理函式（`chatWhoGo`、`chatWhoLater`、清單本身、首頁的選取處理）不呼叫送出或請求函式、不做 POST、PUT、DELETE、不讀 `/api/chats`、不設計時器；聊天頁的清單只接到這兩個函式。
- **18c 聊天頁輸入框只有 Cmd/Ctrl + Enter 送出**（同一個檔，加 `tests/frontend/p51_who.cjs`、`chat.cjs`）：輸入框只有一個 keydown，只在 Enter 加 meta 或 ctrl 時呼叫 `send`；聊天頁沒有別的路徑（keypress、keyup、表單送出、計時器）呼叫它。
- **18d 摺疊的摘要行沒有金額**（同一個檔，加 `tests/frontend/p51_chat.cjs`）：`chatQuietSummary` 只用各種類的次數，不提金額、不讀紀錄的欄位；寫進摘要行的只有它。

另有 `tests/frontend/p51_head.cjs`（頁首、準備頁、清單）與 `tests/test_p51_docs.py`（文件與守門檔都在、帶規則號碼）不屬於守門規則，但一起跑。

## 這版沒有改的邊界

這版沒有碰啟動邊界：`vbear/` 只有 `__init__.py` 的版本號一行不同；沒有新的 API、設定鍵、資料檔、事件種類或瀏覽器 `localStorage` 鍵。`docs/SECURITY-MODEL.md` 只加一小段「Chat reads like text (v0.24)」寫明這一點，不改任何邊界段落。

## 真機驗證

這版的外觀（兩種主題、桌面與 400px 寬、一段有工具紀錄與權限卡片的真對話、換員工的清單往上打開時有沒有被擋住）要由協調者用暫存主控台截圖確認；撰寫者沒有開瀏覽器，排版是依 CSS 與測試推斷的。
結果由發版的人記在 CHANGELOG 的「On a real Mac」。
