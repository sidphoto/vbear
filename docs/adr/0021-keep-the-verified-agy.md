# 0021 保留已驗證的 AGY：聊天安全檢查時把檢查過的那一份存進 VBear 自己的資料夾，AGY 自己更新後，聊天改用這份副本（每次啟動前比對 SHA-256）

日期：2026-11-13　狀態：已決定（v0.26.0；依據使用者 2026-11-13 的要求「工具自己更新不要讓聊天停」，細節由協調者定。這是啟動邊界的變更：依據 ADR 0012、ADR 0018 與 `docs/SECURITY-MODEL.md` 的「Keeping the verified AGY (v0.26.0)」，一律 fail closed，沒有放寬任何既有檢查）

## 背景

Claude Code 的聊天已經只從 Claude 自己的版本資料夾（`~/.local/share/claude/versions/<已驗證版本>`）挑執行檔，Codex 的聊天只從 `~/.codex/packages/standalone/releases/<已驗證版本>-…/bin/codex` 挑。這兩個工具自己更新時，舊版的資料夾還在，所以聊天不會停。

AGY 不一樣：它原地覆蓋 `~/.local/bin/agy`（更新後舊檔還會變成 `agy.<n>.old` 之類的殘檔，但那不是 AGY 承諾的位置，VBear 不使用）。`agy_chat_env.pinned_binary` 取 PATH 上第一個 `agy`、讀 `--version`、查版本表與通過紀錄，所以 AGY 一更新（1.5.7 → 1.5.8），聊天就停到 VBear 出新版、使用者再按一次聊天安全檢查為止。使用者的 AGY 在一週內從 1.5.6 更新到 1.5.8，Gemini 員工因此停了兩次。

另一個事實：通過紀錄（`agy-chat-verified.json`）只記「版本字串」，沒有綁定當時受檢的執行檔（ADR 0018 的殘餘風險已寫）。所以「1.5.7 通過」只是說「某個自稱 1.5.7 的檔通過過」。要把「驗過的那一份」留下來，就要讓紀錄綁得到那一份。

## 決定

1. **驗的就是存的那一份。** 按「驗證聊天」時，VBear 先把 PATH 上的 `agy`（經過 `locate_binary` 同樣的信任檢查：本人或 root 的一般檔案、別人不能改、往上每個資料夾別人不能改）複製到
   `<state>/tools/agy/staging-<隨機>/agy`：資料夾 0700、檔案 0500、`O_EXCL`＋`O_NOFOLLOW` 建立、複製的同時算 SHA-256；複製完再對**副本**跑一次 `--version`，必須等於按下按鈕時讀到的版本。
   驗證子程序用 `--agy <這份副本>` 跑（`--agy` 本來就有；現在它也做 `locate_binary` 那套信任檢查，這是收緊，不是放寬）。子程序自己對副本再算一次 SHA-256 寫進報告（`agy_sha256`、`agy_size`）與通過紀錄（`sha256`、`size`），
   檢查結束後再算一次，兩次不同就不算通過。
2. **通過才保存，沒通過就清掉。** 子程序通過、版本出現在已驗證清單、紀錄的 `sha256` 等於 VBear 複製時算的、VBear 對副本重新算的也一樣，才把 staging 資料夾改名成 `<state>/tools/agy/<版本>/`，然後再用挑選用的同一套檢查完整驗一次（保存下來的東西，真的挑得到）。
   任何一步失敗（含磁碟空間不夠、複製中斷、副本的 `--version` 不符）都刪掉自己建的 staging，聊天安全檢查回報失敗，**不改回「檢查 PATH 上那一份、不保存」**：那會讓「驗的不是存的」悄悄回來。
3. **通過紀錄不存副本的路徑。** 副本的位置永遠由版本推導（`<state>/tools/agy/<版本>/agy`，版本必須是 `VERSIONS` 裡的版本、符合 `X.Y.Z`），紀錄只多 `sha256` 與 `size`。計畫原本寫紀錄多一個 `kept`（路徑）；
   不存，是因為任何一份 JSON 都不該能指定「要執行哪個檔案」。沒有 `sha256` 的舊紀錄（v0.25.6 以前通過的）**不算**：要在新版 VBear 上再按一次聊天安全檢查，才會開始保留。
4. **聊天時挑哪一份（`pinned_binary`，單一入口）：**
   a. PATH 上的 `agy` 通過信任檢查、讀得到版本、版本已認得而且已通過 → 用它（現況不變）。
   b. PATH 上的 `agy` 通過信任檢查、讀得到版本，但版本**不認得**（`unsupported`）或**還沒通過**（`unverified`）→ 從保留副本裡挑最新的一份「全部條件都成立」的：
      版本在 `VERSIONS`、紀錄通過且有 `sha256`／`size`、報告也寫同一個 `agy_sha256`、資料夾鏈沒有連結且是本人的 0700、資料夾裡只有 `agy` 一個項目、檔案是本人的一般檔案且權限剛好 0500 且只有一個名字（`st_nlink` 為 1）、
      大小相符、**整個檔案的 SHA-256 與紀錄相同**、副本的 `--version` 就是它的版本。任何一份有問題就跳過，試下一份較舊的；沒有一份成立就照舊拒絕（`unsupported`／`unverified` 原句）。
   c. PATH 上沒有 `agy`、`agy` 不安全、版本讀不出來 → **不使用保留副本**，維持現在的拒絕。理由：這三種都不是「AGY 自己更新了」，而是「這台電腦的 AGY 狀況不對」，不該由 VBear 悄悄換成另一份去用。
5. **啟動前再驗一次。** 挑選（console 端，每次回答 `status` 與每次開聊天）都是整個檔案重算 SHA-256（235 MB 約 0.2 秒），沒有用版本字串或身分快取代替。daemon 端 `_agy_spawn` 在收到的執行檔位於 `<state>/tools/agy/` 底下時，
   自己再驗一次：路徑必須剛好是那個版本的副本路徑、全部條件成立、整個檔案的雜湊與紀錄相同、檔案身分（六個數字）等於 console 給的。之後 `prepare_agy_chat_launch` → `load_validated` 一直把這六個數字釘到 `Popen` 之前，雜湊與啟動之間改動檔案會被看見。
   不在 `<state>/tools/agy/` 底下的路徑照舊（PATH 上的檔，沿用既有的身分釘住）。
6. **畫面。** `agy_chat_env.status` 走 b 時回 `state="ready"`、`verified=true`、`version` 是**實際會執行的**（保留的）版本，另加
   `kept: {using, installed, installed_state}`（`installed_state` 是 `unsupported` 或 `unverified`）。設定頁與聊天頁用白話說：「你的 AGY 已經自己更新到 X。VBear 先用之前驗證過的 Y 聊天，等 VBear 認得 X 就會換。」
   版本號只從伺服器給的資料取，不寫死（守門 19c）。X 已認得但還沒通過時，聊天頁的 AGY 區塊多一個「驗證聊天」（和 `unverified` 同一個確認區，要先說費用），通過後 X 變成 a，Y 留作保留副本。不用 `innerHTML`、不放 emoji。
7. **空間。** 每個工具最多保留 2 份（保存這一份加上最新的一份）。新的通過時刪最舊的，**只刪** `<state>/tools/agy/<版本>/` 這種名稱符合版本格式、是本人的資料夾、裡面只有一個 `agy` 的項目（先刪檔再刪資料夾，不用遞迴刪除、不跟隨連結）；超過一天的 `staging-*` 殘留用同樣的方式清。
   每份約 250 MB，CHANGELOG 與畫面說明寫明。
8. **設定裡不加刪除或恢復按鈕。** 使用者要回收空間，刪掉 `<state>/tools/agy/`（文件寫了位置）；刪掉後聊天照舊在 AGY 更新時停下。

## 考慮過的其他選項

- **用 AGY 自己留的 `~/.local/bin/agy.<n>.old`。** 那是 AGY 的更新程式的副產品，名稱、數量、何時被清掉都沒有承諾，不是 VBear 驗過的那一份，也沒有雜湊。不選。
- **只記雜湊、不存檔。** 雜湊能認出「這不是驗過的那一份」，卻留不下可以執行的東西；AGY 一更新就沒有可跑的了。不選。
- **硬連結或符號連結到 PATH 上的檔。** AGY 若原地覆蓋，硬連結會跟著變（同一個 inode）；符號連結本來就不能用（路徑不得含連結）。不選。
- **複製失敗就改為直接驗 PATH 上那一份。** 見第 2 點。不選。
- **用版本字串（`--version`）判斷副本。** 這正是現在的弱點。副本一定比對 SHA-256。不選。
- **保留所有通過過的版本。** 每份 250 MB，沒有上限。不選（第 7 點）。
- **AGY 沒有安裝時也用保留副本。** 見第 4 點 c。不選。
- **daemon 端不重驗，只靠 console 給的身分。** daemon 是獨立程序，console 只要被騙就可以給它任何路徑；既有的 PATH 路徑沿用這個假設（ADR 0012），但副本是 VBear 自己保管的東西，可以便宜地獨立驗，所以驗。

## 後果

- 使用者的 AGY 自己更新後，只要之前在 v0.26.0 以後按過聊天安全檢查，聊天不會停：改用保留的舊版。VBear 認得新版後，聊天頁會提示「驗證聊天」，通過後換成新版。
- **要先在新版 VBear 上按一次聊天安全檢查才會開始保留。** 升級前通過的版本沒有雜湊，不算。
- **Google 若拒絕舊版連線，保留的舊版就會失敗**（登入照舊跟著 HOME，但版本太舊時 AGY 可能被服務端擋下）。這不是 VBear 能偵測的事，會以 AGY 啟動或對話失敗的樣子出現；到那時要到終端機更新 AGY 並等 VBear 認得新版。
- Claude Code 與 Codex 這版不改：它們本來就用工具自己保留的舊版資料夾；工具自己清掉舊版資料夾時聊天仍會停（殘餘）。
- **副本不會自己更新**，舊版若有已知的安全問題不會被修。VBear 只在「新版還沒被認得或通過」的期間用它，認得並通過後優先用 PATH 上的新版（a）。
- 同一個使用者的其他程式可以改動副本（`chmod` 後寫入）；VBear 靠每次啟動前的整檔 SHA-256 發現，發現後那一份被跳過（聊天停或改用較舊的）。VBear 不修復、不刪被改過的副本（人工處理）。
- 副本若在執行時自己更新（AGY 的更新程式把舊檔改名成 `agy.<n>.old`、寫新的 `agy`），資料夾裡多了項目，下次挑選時整份被跳過；這是第 4 點「資料夾裡只有 `agy`」的用意。AGY 在 ACP 模式下會不會這樣做，沒有驗證過。
- 副本放在 VBear 的狀態資料夾，離開工作資料夾與 AGY 的設定資料夾；它能否離開原本的位置執行（AGY 是單一檔案，內建內容在檔案裡，執行時才寫進聊天用的設定資料夾）是由第一次真的檢查證明的，沒通過就沒有保存。
- 守門 25（`tests/test_autonomy_guard.py`）：副本只在 `<state>/tools/agy/<VERSIONS 裡的版本>/agy`；挑選與啟動前一定比對 SHA-256；版本不在 `VERSIONS` 或沒有通過紀錄的副本絕不啟動（有雜湊不符、版本不認得、副本是連結、群組可寫、紀錄沒有雜湊、資料夾多一個項目、多一個名字的壞樣本）；驗證子程序用的是副本；紀錄裡的雜湊來自副本。守門 1–24 一字不改。
