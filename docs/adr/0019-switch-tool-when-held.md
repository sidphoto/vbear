# 0019 員工用的 AI 工具被擋住、自己修不了時，在看到原因的地方給「改用另一家」一顆按鈕（補 ADR 0017 第 4 點）

日期：2026-11-12　狀態：已決定（v0.25.1；使用者把介面改版交給協調者主導。細節依 ADR 0001、0002、0014、0017、GLOSSARY 與 `docs/SECURITY-MODEL.md` 的「Switch the AI tool of a held-back employee (v0.25.1)」）

## 背景

ADR 0017 讓「AI 工具不能用的原因」用白話說，並在沒有員工時給一頁做完的第一次使用。但已經有員工、而他用的 AI 工具被擋住時，畫面只說「現在還不能聊天」和一顆「先把聊天準備好」（首頁），或一顆「到 AI 工具看看」（準備頁）。
有兩種擋住是使用者自己修不了的：
- **管理員設定**（`policy`）：這台電腦有公司的管理員設定，VBear 不能用該工具聊天。這條安全規則不能動、不能繞。
- **版本不認得**（`unsupported`）：工具自己更新到 VBear 還不認得的版本，只能等 VBear 出新版。

使用者的 CEO 就是用 Claude 建的，而這台電腦有管理員設定。要換成 ChatGPT（Codex），得自己找到「員工 → 設定 → AI 工具」，看不出這是出口。畫面沒有在看到原因的地方說「那就讓這位員工改用別家」。

## 決定

1. **在看到原因的兩個地方，給「改用另一家」。** 首頁 CEO 的區塊（`homeAsk` 的不能聊天那一段）與準備聊天的頁（`#/chat?profile=…`）。條件：`chatPrepState` 的結果是 `policy` 或 `unsupported`，而且別家有選項。其他狀態（還沒做安全檢查、還沒登入、讀不到）使用者自己做得到，照舊只有原本那顆按鈕。
2. **選項只來自頁面已經讀到的 `GET /api/chats` 的 `support`。** 不多讀任何 API。別家列出來的條件：可以聊天（`ready`／`verified`）、或下一步是使用者自己做得到的（要做一次聊天安全檢查、安全檢查還在做、聊天用的 Codex 要登入）。同樣被擋住的（`policy`、`unsupported`、`folder`、`hooks`…）不列；沒安裝的是一行淡字「還沒安裝，不能改用」，沒有按鈕，讓人看得出為什麼只剩一個選項。能聊的排前面，每個選項旁照實寫它的狀態。一家都沒有時，畫面和原來一樣（原句、原連結）。
3. **按下去不會馬上改。** 第一下只展開確認區（同一頁，不用瀏覽器的 confirm）：「{員工} 之後會改用 {工具} 聊天」；「之後跟他說的話會送到 {公司}（原本設定的是 {舊公司}）」（資料流向改變，句子不收進任何摺疊）；「之前用 {舊工具} 聊的對話會留著，可以看，但不能接著聊；要聊請開新對話」（依據：聊天的引擎在開聊天時就定了，伺服器對換過工具的卡送訊息會回 `card_tool_changed`）；模型用該工具自己的預設；名字、說明、技能和其他設定照舊；記憶與共用資料夾只有使用者打開過的才會帶，打開過的內容之後也送到新那一家。
   焦點移到確認區本身（不是「確認」鈕），避免連按兩次 Enter 就確認。「先不要」關掉並把焦點還給剛才那顆按鈕。確認區的狀態放在頁面自己的物件裡，重畫與 5 秒更新不會送出也不會關掉它。
4. **只有「確認」那一下寫入，而且是員工設定本來就有的寫入。** 一次 `POST /api/agent-profiles/<id>`，body 只有 `{"model": {"tool": …, "model_id": ""}}`：與員工編輯表單換工具時是同一個寫入、同一個欄位。`model_id` 空字串是「工具預設」，與新員工表單、首頁第一次建立 CEO（`ceoCreate`）、一次新增幾位常用的員工用的是同一個值，不從 catalog 猜模型名。啟動方式、權限、說明、技能、名字一律不送（伺服器對沒帶的欄位保留原值）。
   伺服器拒絕時用 `plainWords` 白話顯示原因，員工維持原樣，確認區留著可再試或關掉；沒有收到回覆時說「不確定有沒有改成」，不猜。連按「確認」只寫一次。
5. **換完之後，接上那一家原本的流程。** 成功後重新讀一次（準備頁：既有的 `refresh`；首頁：重新畫整頁），同一個位置變成新工具的狀態：能聊就能聊；還沒做聊天安全檢查就出現既有的檢查按鈕（它自己有確認與費用說明）。不自動檢查、不自動登入、不自動開對話、不自動送訊息。
6. **原因句講得出下一步。** 管理員設定：「這台電腦的 {工具} 有管理員設定，VBear 不能用它聊天。這不是你能改的；可以讓 {員工} 改用別家 AI。」沒有別家可換時維持原句。版本不認得的句子不變，下面多一行「現在要聊的話，可以讓 {員工} 先改用別家 AI：」。
7. **舊對話不再被當成「和這位員工的對話」去送。** 首頁與「換人」用的 `homeChatsOf` 只挑引擎等於員工現在工具的對話；舊工具的對話仍在對話紀錄裡可以看。否則換工具後，首頁的送出會把話送進舊對話，被伺服器用 `card_tool_changed` 拒絕。

## 沒有改的

- `policy`、`unsupported`、聊天安全檢查、`admin_policy` 的任何判斷；換工具這件事在 `vbear/` 底下除了版本號一個字沒改（同一版另有兩處與換工具無關的追加：一、「試一下」失敗時不再一律說「還沒登入」，動 `vbear/setup_try.py` 與 `vbear/headless_cli.py`，見守門規則 21d；二、失敗的回合要看得到並留下原因，動 `vbear/runtime/failure_words.py`（新）、`codex_chat_protocol.py`、`codex_chat_session.py`，見守門規則 18e；兩者都見 CHANGELOG v0.25.1）。沒有新增 API 路徑、請求種類、設定鍵、聊天事件、`localStorage` 鍵。
- 每一步仍然是使用者自己按：頁面不替人選一家（不預選、不標建議；順序只依「現在能不能聊」）、不自動換、不自動檢查。
- 員工編輯表單、開始設定頁、員工頁、守門 1–19 一個字沒改。

## 考慮過的其他選項

- **按一下就換**：資料流向會變（話改送到另一家公司），一定要先確認，不做。
- **自動換成唯一可用的一家**：替人決定，不做。
- **只在員工頁加按鈕**：使用者看不到，這就是原來的問題。
- **從 catalog 取該工具的預設模型名**：多一個讀取、而且要猜；「工具預設」（空字串）是現成的、其他三處已在用。
- **換工具時把技能與職業標籤一起清掉（像編輯表單）**：body 就不只 `model`；技能卡留在員工卡上不影響聊天，之後可在員工表單移除。
- **把「還要做一次安全檢查」的選項也在這裡替人做完**：安全檢查有自己的確認與費用說明，不重做一份。

## 後果

- 被擋住的人在看到原因的地方就有出口；沒有別家可用的人，畫面和 v0.25.0 一樣。
- 換工具後，技能卡與職業標籤留在員工卡上（只換了工具和模型）；新工具不讀的技能卡可到員工表單移除。
- 記憶與共用資料夾是每位員工自己的開關：打開過的，換工具後內容會送到新那一家公司；確認區有寫。
- 沒有在真的電腦上用真的工具試過（測試用假資料）。

## 守門規則 21（寫成測試，規則 1–19 一條沒放寬）

- **21a 換工具的寫入只由確認鈕的 click 送出**（`tests/frontend/p57_switch.cjs`）：第一下、「先不要」、重畫、5 秒更新、Enter 都不送；程式裡這一段只有 `switchToolConfirm` 一個寫入，它只被確認鈕的 click 呼叫。壞樣本：另一個函式裡多一個請求、在確認函式裡多寫一次、用 keydown 或計時器呼叫確認、確認前就寫、確認後沒寫或寫兩次，都會被抓到。
- **21b 那個寫入的 body 只有 `model`**（同一個檔）：`{model: {tool, model_id: ""}}`，tool 是畫面上列出的另一家；多一個欄位（名字、啟動方式、說明、技能、`enabled`）、指定模型名、換成不是按的那一家、換成原本的工具、寫到別的路徑，都會被抓到。
- **21c 確認區一定有資料流向那一句，而且不在摺疊裡**（同一個檔）：「之後跟他說的話會送到 {公司}」與確認鈕在同一個區域；壞樣本：少了那一句、公司不對、放進 `details`、沒有確認鈕。
- **21d 「試一下」失敗時，工具印在錯誤輸出的東西看過就丟**（`tests/test_autonomy_guard.py` 的 `SetupTryStderrRules`，與 `tests/test_setup_try_failures.py`）：`headless_cli.run(stderr_tail=…)` 保留的最後 4 KiB 只以 `HeadlessError.stderr_tail` 交出；`vbear/setup_try.py` 只把它交給 `classify_failure`，不放進變數、結果、訊息、檔案或日誌，`classify_failure` 只回固定的詞。壞樣本：存進變數、放進結果（值或鍵名）、寫日誌、組成文字、分類函式回傳原文或印出來、執行器把尾巴寫檔、印出、放進例外訊息、回傳、複製，都會被抓到；執行時的測試用一段編造的錯誤輸出，檢查結果、日誌和程式寫下的每個檔案都找不到它。
- **18e（接在守門 18 後面，只加，同一版追加）**：失敗的回合不得被判成安靜紀錄（`tests/test_autonomy_guard.py` 的 `FailedTurnIsNotQuietRules`，與 `tests/frontend/p51_chat.cjs`）：`chatIsQuiet` 對 `is_error` 為真的 `turn_ended` 一律回 false，`chatLine` 對 reason 為 `result` 且 `is_error` 為真的回合直接寫「這一回合沒有成功」。壞樣本：拿掉檢查、只認 `=== false`、檢查放在別的種類、沒有失敗句子、句子沒有顯示，都會被抓到。這是 ADR 0016「不正常的事永遠直接看得到」被漏掉的一處。

守門 15、16 系列一個字沒改；`tests/test_autonomy_guard.py` 只加了第 21 條的說明與檢查檔案存在、帶有規則編號的 `Guard21FilesAreThere`（20 與 ADR 0018 是另一版的）。
