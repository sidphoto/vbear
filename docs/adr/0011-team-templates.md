# 0011 團隊範本是用的人在瀏覽器勾選、套用的一組現成員工、技能與例行工作：只經原本的建立路徑、不打開任何東西、可以復原沒改過也沒用過的

日期：2026-11-08　狀態：已決定（使用者 2026-11-08 拷問拍板，見文末「使用者拍板」第 1–7 點；細節依 ADR 0001–0010 與 GLOSSARY 提出；
第 4、5、6 點是使用者可以再改的取捨，改的話要連同畫面文字與 `docs/SECURITY-MODEL.md` 一起改）

## 背景

路線圖第 8 項 v0.19.0「團隊範本」，是 P36 拍板要搬進來的 Grok Bot／Open_Bot 做法的最後一批（「…→ 存成技能、定時任務 → 團隊範本」）。
ADR 0003 寫過：「幕僚長派工、例行工作、團隊範本都會碰到這個原則」——預設「AI 提議、你確認」，三件永遠不准做的事（調高花費上限、讓員工用完整模式出發、從網路裝技能）不因任何東西放開。
ADR 0001：目標使用者沒開過終端機，預設要更保守；ADR 0002：員工預設安全模式；ADR 0008、0009：記憶（Claude Code 的卡預設帶、Codex 的卡預設不帶）與共用資料夾（預設每位都關）只由用的人一位一位打開；
ADR 0010：技能與例行工作只有用的人能建，例行工作到時間自己開始要勾自己動手第 3 項。

到 v0.18.0 為止：

- 角色卡、技能、例行工作各有自己的寫入函式（`agent_profiles.save_profile`／`delete_profile`、`skillbook.add`／`delete`、`routines.create`／`delete`），只在 `server.py` 的瀏覽器路由被呼叫（帶 `X-VBear`），
  各有自己的檢查（封閉的欄位、`memory_rules.check_text`、員工要能聊天、上限：角色卡 500、技能 100、例行工作 20）；守門測試（規則 1–12）保證幕僚長、派工、群組、記憶、共用資料夾、技能、例行工作的模組碰不到彼此的寫入函式。
- 起手牌組是唯一「一次拿幾張現成的卡」的路：瀏覽器一張一張 `POST /api/agent-profiles`，沒有紀錄、沒有復原。自己動手第 1 項讓派工建員工，一律安全模式、沒有技能卡，可以「撤回（停用）」，不刪。
- 技能的 `source.how` 與例行工作的欄位都是封閉集合：多一個值，舊版會把整份檔案當成讀不懂。
- 畫面上已經有「角色範本」（職業，掃描到的 Agent 角色）與「任務範本」（任務卡）兩個詞，GLOSSARY 的「技能」條目也要避免短稱；所以這個功能的正式名稱寫全，叫「團隊範本」。

## 決定

1. **團隊範本 = 一組現成的員工（角色卡）、技能、例行工作；不含群組、記憶、共用資料夾開關、聊天、完整模式、技能卡、AI 工具。**
   有 VBear 內建的四個（小店、自媒體、接案工作室、個人生活助理，合起來 12 位員工、12 個技能、6 件例行工作；內容寫在程式裡，全部繁體中文、不含個人資訊、每段都過 `check_text` 沒有警告），
   和用的人自己存的（最多 20 個）。只存在這台電腦，不匯出、不匯入、不上傳。正式名稱「團隊範本」，畫面上一律寫全，不縮短。
   理由：使用者拍板（第 1、2、4 點）；名稱寫全才不和「角色範本」「任務範本」「技能」混在一起。

2. **只有用的人在瀏覽器套用、存、復原；套用只經原本的寫入函式，守門規則 13b 沒有為套用開例外。**
   套用是 `server.py` 的新路由（帶 `X-VBear`）：先檢查全部（檔案讀得懂、套用後不超過上限、例行工作的員工能聊天、要多確認的字已確認），再一個一個建：
   員工用和 `POST /api/agent-profiles` 同一段程式（抽成 `_save_card`），技能用 `skillbook.add`，例行工作用 `routines.create`，檢查一條都不少。
   團隊範本的模組（`template*.py`）只做格式、內建內容、計畫與紀錄，碰不到任何寫入函式；幕僚長、派工、群組、例行工作、記憶、共用資料夾、技能、自己接續的模組不能 import 團隊範本的模組（守門規則 13a–13e）。
   **規劃時曾打算替 `templates_apply` 在規則 13b 開一個最窄的例外，實作後發現不需要：所有寫入都在 `server.py`（寫入函式本來就從那裡被呼叫），`templates_apply.py` 只記紀錄、算規則，自己不叫任何卡、技能、例行工作的寫入函式。**
   所以沒有為套用開例外，13b 和以前一樣嚴；測試把同樣的呼叫放進任何一個團隊範本的模組，仍然被抓。沒有「AI 提議團隊範本」，所以不新增自己動手的項目，ADR 0003 的五項不變。
   理由：ADR 0003（AI 提議、你確認）；同一組檢查讓團隊範本不會變成繞過上限與內容規則的路；不開例外比開例外更窄。

3. **套用不打開任何東西、不用 AI、不花錢。**
   整組員工用用的人選的一個 AI 工具（Claude Code 或 Codex，預設是開始設定頁顯示就緒的那個），**一律安全模式**、沒有技能卡；模型照團隊範本的建議（Codex 用它自己的預設）；
   記憶與共用資料夾照卡的預設（團隊範本不呼叫它們的開關）；**例行工作建好一律關著**，要用的人自己到例行工作頁打開（之後照 ADR 0010：到時間只提醒，勾了第 3 項才自己開始）。
   套用不呼叫聊天、daemon、會議引擎或任何 AI 工具；`config.json` 與自己動手不變。Codex 的卡也是安全模式，所以在 VBear 裡只能聊天、不能在終端機出發（照派工建 Codex 卡的先例）。
   理由：使用者拍板第 3、7 點；ADR 0002、0008、0009。

4. **每次套用都可以「復原這次套用」：先列出要刪的，再刪；只刪這次建的、沒改過也沒用過的；寧可多留。**
   - 套用紀錄 `<state>/templates/applies.json` 記每一項的 id、指紋（員工用 `profile_digest`，技能與例行工作用整筆紀錄的 sha256）與狀態，不記名稱與內容；最多 50 次。
   - 員工：卡沒改過（含停用、名字、指示、模型）、記憶與共用資料夾開關沒改過、沒有任何聊天、群組、派工、會議、組隊會議、任務卡提到他、沒有留下來的例行工作交給他，才刪。
   - 例行工作：沒改過、沒打開過、`runs.jsonl` 沒有任何一筆（提醒、錯過、跳過、做過都算），才刪。
   - 技能：沒改過才刪。VBear 不記錄技能有沒有被用過（用技能只是把字放進輸入框，送出的是用的人自己的話），所以只看有沒有改過；刪掉的字和團隊範本一模一樣，再套用就回來。
   - 讀不到、讀不懂、太大（單一檔案超過 4 MiB）、太多（超過 20,000 個檔案）、是連結 → 當作用過，留著。中斷的套用裡 id 不確定的一律不刪。復原只碰紀錄裡建好的 id，**永遠不改、不刪套用之前就有的東西**。
   - 刪的時候伺服器再算一次，只刪預覽裡有、而且現在仍然可以刪的；順序例行工作 → 技能 → 員工；用頁面上「刪除」同一組函式。
   - **VBear 看不出用的人有沒有在終端機用過團隊範本的員工。** 照程式查過：終端機以安全模式出發時，角色卡的 id 只在記憶體裡的預覽出現，交給 runtime 的 spec 與寫進 `<state>/sessions/` 的紀錄都沒有卡的 id；完整模式出發不留任何紀錄。
     所以「用過」的判斷在這一條路上是看不到的，復原預覽只要會刪員工，就固定多一行提醒（「如果你在終端機用過這些員工，VBear 看不出來；確定再刪。」），由用的人確定再按「刪掉這些」。
     測試（`tests/test_templates_undo.py`）釘住這個事實；哪天終端機出發會留下卡的 id，這三個測試會失敗，那時才可以拿掉那一行並讓復原去查。
   理由：使用者拍板第 5／6 點④；「用過」寧可多算，因為刪錯是弄丟用的人的東西，留錯只是多一張卡；看不到的地方不假裝看得到。

5. **超過上限整次不套用；中途出錯就停下並可以復原。**
   套用前算好角色卡 500、技能 100、例行工作 20；超過就整次不套用，畫面寫差幾個。一次套用最多 12 位員工、24 個技能、12 件例行工作。
   預檢之後還是出錯（例如另一個分頁剛好存滿技能）→ 停在那一項，已建的記在紀錄，畫面說建了哪些、可以復原。
   理由：不留一半又沒紀錄的東西；上限是 v0.18.0 本來就有的，團隊範本不另外放寬。

6. **存成自己的團隊範本存的是當下的複本，只帶做事的方法，不帶開關與紀錄；完整模式的員工可以存，但不帶啟動模式，套用一律是安全模式。**
   員工帶名字、職位、用的人寫在卡上的固定指示、Claude 的模型別名；不帶 AI 工具、完整模式（啟動模式）、技能卡、職業、權限意圖、停用與否、記憶與它的開關、共用資料夾開關、聊天紀錄、工作資料夾。
   所以完整模式的員工也可以存進團隊範本，但存下來的東西裡沒有任何啟動模式；之後套用，新員工一律是安全模式。畫面在存的對話框、存完的回應裡明說這一點。
   技能帶名稱與內容；例行工作帶名稱、內容、星期、時間與交給哪一位（那一位也有存才帶），不帶打開與否、執行紀錄。存之前每段字再用 `check_text` 檢查。可以改名、刪除，不能改內容。
   理由：使用者拍板第 2、3、5／6 點③；不帶開關，套用時才不會打開用的人當下沒打開的東西；完整模式的員工是用的人的選擇，不是團隊範本能複製的東西。

7. **原本的檔案格式一個欄位都不加。** 團隊範本建的技能記成 `source: {how: "typed"}`，角色卡與例行工作也只用原本的欄位；「是團隊範本建的」只記在 `<state>/templates/`。`vbear/runtime/` 與啟動邊界不改。
   理由：回到 v0.18.0 時每樣東西都讀得懂、照常能用。

## 考慮過的其他選項

- **像起手牌組一樣由瀏覽器一張一張 POST**：最少新程式，但沒有伺服器端的套用紀錄，就做不出可靠的「只刪這次建的」；也沒辦法先檢查上限再動手。不選；起手牌組不變。
- **在角色卡、技能、例行工作上加一個「從團隊範本來」的欄位**：復原時最好找，但 v0.18.0 的封閉格式會把整份檔案當成讀不懂（技能的 `source.how` 尤其）。不選；另記在 `templates/`。
- **給團隊範本自己的寫入函式（直接寫 `agent_profiles.json` 等）**：可以做成一次全有或全無，但等於多一條繞過原本檢查的路，也違反守門規則的「寫入函式只在路由」。不選。
- **替 `templates_apply` 在守門規則 13b 開一個最窄的例外**：規劃時的想法，因為以為套用的寫入要在那個模組裡。實作時寫入都留在 `server.py`，模組只記紀錄，不需要；沒有例外比有例外更窄。不選。
- **團隊範本帶 AI 工具、記憶、共用資料夾、完整模式的設定**：最完整的「一鍵複製一整組」，但套用就會打開用的人當下沒打開的東西（ADR 0002、0008、0009）。不選（使用者拍板第 3 點）。
- **套用時例行工作照團隊範本打開**：最省事，但會讓沒看過例行工作頁的人在某個早上開始花錢（就算只是提醒，也是他沒選過的）。不選（使用者拍板第 7 點）。
- **復原用時間判斷（例如 24 小時內）或只看名字**：簡單，但會刪到用的人已經聊過或改過的東西。不選；用指紋＋紀錄，寧可多留。
- **技能也記「用過」**：要在聊天紀錄或技能檔加欄位（違反第 7 點），或讓 VBear 比對送出的訊息（會讀用的人的對話內容）。不選；只看改過，並在畫面寫明。
- **讓終端機出發也留下卡的 id，復原才查得到**：要改啟動邊界（`agent_launch.py`、`runtime/agent_sessions.py`），這版一行都不改 `vbear/runtime/`。不選；用固定的一行提醒，由用的人確定。
- **讓幕僚長依用的人的描述挑團隊範本或提議團隊範本**：像 Grok Bot，但那是新的「AI 提議」路徑，要另開 ADR 與自己動手的項目。不在這版。
- **匯出匯入團隊範本檔**：方便分享給朋友，但匯入的檔案是不受信任的內容（固定指示、例行工作內容會變成送給員工的話），要另外設計檢查與說明。不選（使用者拍板第 2 點）。
- **AGY、Grok、MCODE 的員工**：它們還不能聊天，例行工作交不了，安全模式也不能出發。不選；等它們能聊天再說。

## 後果

- 導覽多「團隊範本」（`#/templates`）；角色卡池多「用團隊範本開始」。新的 API：`GET /api/templates`、`POST /api/templates/preview`、`/apply`、`/applies/<id>/undo-preview`、`/applies/<id>/undo`、`/mine`、`/mine/<id>`、`/mine/<id>/delete`。
- 新的紀錄：`<state>/templates/`（`mine.json`、`applies.json`、`log.jsonl`），都 0600、只在這台電腦；`applies.json` 與 `log.jsonl` 沒有名稱與內容。
- 沒有新的對外資料路徑：套用不送任何東西給 AI 公司；之後跟團隊範本建的員工聊天，和跟任何員工聊天一樣（Claude Code 送到 Anthropic、Codex 送到 OpenAI）。
- 守門測試多規則 13a–13e（團隊範本的模組受規則 1–12 的掃描；別的模組不能 import 團隊範本的模組；團隊範本裡的 `enabled` 只能是 `False`；套用紀錄與自己的團隊範本的寫入函式只在 `server.py` 和各自的模組）。
- `vbear/runtime/`、啟動邊界、`config.json`、自己動手、聊天／派工／群組／記憶／共用資料夾／技能／例行工作的檔案格式都沒有改。
- 殘餘風險（寫進 SECURITY-MODEL 新的「Team templates (v0.19)」）：
  - 內建團隊範本的固定指示與例行工作內容會變成送給員工的話；它們由 VBear 寫在程式裡、每段過 `check_text`，但模型會不會照做沒有保證（沒有在真機上驗證；這版只驗一位員工能聊天）。
  - 自己存的團隊範本的字來自用的人自己的卡、技能、例行工作（包括從員工的話存成的技能）；套用時照原本的檢查再過一次，要多確認的再問一次。
  - 「用過」的判斷靠 VBear 自己的紀錄；VBear 看不出用的人有沒有在終端機用過員工，也沒有技能「用過」的紀錄（技能只看有沒有改過）；VBear 沒有紀錄的用法（例如用的人把技能的字複製到別處）也看不到。復原預覽固定多一行提醒，最後由用的人確定。
  - 員工被允許的指令可以讀到 VBear 的存取權杖並呼叫 VBear 的 API（和所有路由相同，ADR 0010 寫過）；用的人不允許那樣的指令就不會發生。
- 回到 v0.18.0 時（依程式推，沒有實際跑）：`<state>/templates/` 留著、不被讀，不能復原，要刪就到角色卡池、技能頁、例行工作頁一個一個刪，什麼都不會被刪；團隊範本建的員工、技能、例行工作都是 v0.18.0 本來的格式，照常能用（例行工作仍是關著的）；
  再升級回來時復原照樣能用，在 v0.18.0 改過、用過的會被留著。見 CHANGELOG。
- 沒有在真機上驗證的事（照實寫）：Codex 員工（暫存狀態沒有聊天用的 Codex 登入）；內建團隊範本建的例行工作真的到時間做一次（建好是關著的，v0.18.0 已驗過例行工作本身）；模型會不會照內建的固定指示與技能做。
  真機驗證（Claude Haiku、`tools/qa_p45.py`，一位員工一個回合）的結果寫在 CHANGELOG。

## 使用者拍板（2026-11-08）

1. 團隊範本的內容：員工（角色卡）加技能加例行工作，不含群組。
2. 來源：VBear 內建幾個，加上使用者把自己現有的員工、技能、例行工作存成自己的團隊範本。只存在使用者的電腦裡，不做匯出匯入。
3. 套用時使用者選一個 AI 工具（Claude Code 或 Codex，預設已登入的），整組員工都用它；一律安全模式，團隊範本永遠不建出完整模式的員工；記憶、共用資料夾照使用者的預設，團隊範本不打開。
4. 內建四個：小店（客服、商品文案、會計；例行：每天整理昨天的花費、每週想下週促銷）、自媒體（選題、寫稿、社群編輯；例行：每天早上整理新聞選題、每週排下週內容）、
   接案工作室（專案助理、報價與合約草稿、會計；例行：每週一整理本週待辦）、個人生活助理（行程助理、學習教練、記帳；例行：每天早上排今天的事）。
5. 像樂高積木：①套用前可以勾選只要哪幾位員工、哪幾個技能、哪幾件例行工作；②可以從幾個團隊範本各拿一些拼在一起；③拼好的組合可以存成自己的團隊範本。
