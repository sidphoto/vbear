# 0010 技能是用的人存的做法、用的時候才送；例行工作只在 VBear 開著、Mac 醒著時做，到時間自己開始要勾第 3 項，暫停的派工自己接續要勾第 5 項

日期：2026-11-08　狀態：已決定（使用者授權「一路做到 v0.18.0，細節依決策紀錄決定」，依 ADR 0001–0009 與 GLOSSARY 提出；
使用者 2026-11-08 再拍板一件事：例行工作每天上限的預設是每天上限的一半。
第 2、5、6、7 點是使用者可以再改的取捨，改的話要連同畫面文字與 `docs/SECURITY-MODEL.md` 一起改）

## 背景

路線圖第 7 項 v0.18.0「存成技能與例行工作（含倒數接續、醒來補做）」，是 P36 拍板要搬進來的 Grok Bot／Open_Bot 做法（「存成技能、定時任務」）。

ADR 0003 已經定了：自己動手第 3 項「例行工作可以自己啟用、定時執行」、第 5 項「碰到上限暫停的工作，倒數結束後自動接續」，預設都不勾；
補充 Q6：VBear 不在雲端跑，Mac 睡著或 VBear 關著時不做任何事；醒來或打開時列出錯過的例行工作與到期的接續，用的人選要補做哪些；勾了第 3 或第 5 項的自動補做；
另有一個預設不勾的「有工作在跑時不讓 Mac 睡著」；不採用「錯過就跳過」。ADR 0001 Q4-1：每天上限在本機明天 0 點恢復，方案用量上限照 AI 工具說的時間倒數。
ADR 0006 第 4、6、8 點：第 3、5 項跟著 v0.18.0 做；派工暫停時「繼續」只由用的人按，被打斷的那一步不重做。ADR 0007 第 3、6 點：群組只有用的人說話才有員工回答，不倒數、不自動繼續（留給 v0.18.0）。

到 v0.17.1 為止：

- VBear 的「技能卡／技能庫」是**唯讀掃描** AI 工具自己的技能檔（`SKILL.md`），插在角色卡上只是挑選紀錄：安全模式的 Claude Code 聊天（`--safe-mode`）不載入技能，
  Codex 聊天關掉了技能說明。ADR 0003：AI 不能自己從網路安裝新技能。
- 聊天：每個指令、每個檔案修改都問；**卡片 5 分鐘沒回覆就過期、當作拒絕**；回合 10 分鐘逾時；每回合上限預設 US$0.50；同時最多 3 個聊天程序。
- 派工暫停時已經記下 `reason` 與 `until`（每天上限 → 本機明天 0:00；方案用量上限 → AI 工具回報的恢復時間，**只有 Codex 會回報**，Claude Code 是「未知」），但沒有倒數、沒有到期處理。
- VBear 的 macOS App 關掉最後一個視窗就結束 App 與它啟動的 server。產品程式沒有任何計時執行、launchd、`caffeinate` 或 `pmset`。
- P42-6 的真機發現：Claude Code 用 `--resume` 接續時不套用新的系統指示，所以任何「改了就送進系統指示」的東西只有新聊天才看得到。

## 決定

1. **技能是用的人存在 VBear 裡的一份做法（名稱＋最多 4,000 字），用的時候才送，送出的是用的人自己的話。**
   - 存在 `<state>/skillbook/skills.json`，最多 100 個。不寫成任何 AI 工具的技能檔、不插在角色卡上、不進系統指示（所以 `vbear/runtime/` 的啟動、`prompt_sha`、`chat-prompt` 都不動，P42-6 的問題碰不到）。
   - 用法：聊天與群組的輸入框按「用技能」，文字放進輸入框，用的人看過、可以改，再按送出；或當例行工作的內容（從技能帶入，複製當下的文字）。
   - 和「技能卡」分開：技能卡是 AI 工具自己的技能檔，VBear 只列出來。頁面「技能」（`#/my-skills`）最上面寫明兩者是兩回事。
   理由：目標使用者（ADR 0001）要的是「做得好的做法存起來下次再用」；放在用的人的訊息裡，權威和用的人打字一樣、看得到、每次都經過他；
   寫成 `SKILL.md` 會動到用的人自己的 AI 工具設定，而且 VBear 的安全模式聊天本來就不載入技能。

2. **只有用的人能存技能。** 三條路，最後都是用的人在瀏覽器按「存」（帶 `X-VBear`）：在技能頁自己寫；在聊天或群組某句話旁按「存成技能」
   （員工的話要勾「我確定」，對話框寫「這段是員工寫的，存成技能後，你用它時會變成你對員工說的話」）；在一對一聊天按「整理成技能」，
   VBear 用和「整理要記住的事」同一個沒有工具的會議引擎（每次最多 US$0.10，對話送到 Anthropic，需要 Claude Code）提議一個技能，用的人改好再存，整理的程式自己不存。
   名稱與內容用記憶的同一組規則檢查（擋下金鑰、密碼、帳號、付款與身分資料；像在叫員工不問就做事、電話地址要多確認一次）。紀錄只記動作，不記內容。

3. **例行工作 = 一位員工＋一段內容＋星期幾與 1–3 個時間；只有用的人能建、改、啟用、停用、刪除。** 最多 20 件、同時啟用 10 件。
   每一次都用 `ChatService` 開一個**新的一對一聊天**、送一個回合（新的 `send_for_routine`，只收例行工作開的聊天、瀏覽器叫不到、不帶 `origin`），
   所以聊天的規則一條都不變：安全模式、每個指令與檔案修改都問、卡片 5 分鐘過期當作拒絕、每回合上限、每天上限、記憶與共用資料夾照那位員工的開關。
   送出的字前面加 VBear 固定的一句：這是用的人排定的例行工作、他可能不在電腦前、要跑指令改檔案照舊會問他、沒有回覆會當作拒絕。
   一次只做一件；同一件例行工作的同一個時間（slot）**最多開始一次**；送出與記錄之間中斷時不自己重送（照派工的 `uncertain`）。
   幕僚長的提議格式不變，不能提議例行工作；員工說什麼都不會建立例行工作。

4. **自己動手第 3 項 =「例行工作到時間自己開始，醒來時自己補做」；不勾時到時間只提醒。**
   - 不勾（預設）：到時間 VBear 記下「到時間了」，每一頁上方提醒，用的人按「現在開始」或「這次跳過」；不送任何東西、不花錢。
   - 勾了：到時間自己開始，列在「AI 自己做了什麼」（自己動手第 3 項）。
   - ADR 0003 的字是「自己啟用、定時執行」。這版沒有任何 AI 會提議例行工作，建立與啟用永遠是用的人做，第 3 項不能讓任何東西被建立或啟用；
     之後若讓幕僚長提議例行工作，要另開 ADR 決定第 3 項的「自己啟用」怎麼作用。
   理由：「定時執行」本身就是第 3 項（ADR 0003），預設不放；到時間的提醒仍然讓沒勾的人一鍵就能做。

5. **花錢：每次 ≤ 每回合上限；例行工作有自己的每天上限；每天上限照舊是硬上限。**
   例行工作每天上限存在 `<state>/routines/settings.json`（不在 `config.json`），預設是每天上限的一半，用的人在例行工作頁改，不能高於每天上限；
   今天例行工作花到這個數之後就不再開始新的一次（正在做的那次最多再花一回合）。被上限擋下的例行工作記「跳過」，不倒數、不接續，下一個時間照常。
   理由：用的人不在電腦前時例行工作還在花錢，要留一部分給他自己；只有一個回合的例行工作在半夜接著做沒有意義。

6. **Mac 睡著或 VBear 關著時什麼都不做；醒來時只補最近一次。**
   - 不裝 launchd、LaunchAgent、登入項目、crontab，不排 `pmset` 喚醒，不改 App 的生命週期：VBear 的視窗要開著、Mac 要醒著，例行工作頁寫明。
   - 偵測：每 60 秒寫心跳；牆上時間跳過 90 秒以上（睡著）或啟動時心跳太舊（關著），中間的時間都算錯過；只從 `max(啟用時間, 上次心跳)` 算起、最多往回 7 天；沒有心跳（剛升級）不算錯過。
   - 補做：每件例行工作不論錯過幾次只補最近的一次。勾了第 3 項而且最近一次錯過在 12 小時內 → 自己補做，每次醒來最多 3 件、一件做完再做下一件；
     其他（沒勾、超過 12 小時、超過 3 件）列在「等你決定」由用的人選「補做」或「不用了」；下一個時間到了或 24 小時後自動收起。
   - 「有工作在跑時不讓 Mac 睡著」（預設關，例行工作頁的開關）：有例行工作在跑或派工在進行時，VBear 跑 `/usr/bin/caffeinate -i -w <console pid>`（固定 argv、不經 shell），
     沒工作 30 秒後結束；只擋閒置睡眠，闔上蓋子照樣睡，也不會為了到時間把 Mac 叫醒。
   理由：ADR 0003 Q6 選 A（不在雲端、睡著不做、醒來列出、勾了自動補做）；12 小時與 3 件是這版加的上限：補做是要趕上，不是把錯過的全部重做一遍，
   也避免出門幾天回來一打開就花掉一堆錢。

7. **倒數接續只作用在派工；群組只倒數。**
   - 派工因每天上限（本機明天 0:00）或方案用量上限（AI 工具說的時間）暫停時，派工頁、「等你決定」倒數；恢復時間未知（Claude Code 目前都不說）時寫「AI 工具沒說什麼時候恢復」，沒有倒數。
   - 到了恢復時間＋2 分鐘，VBear 再看一次今天的燈與那個 AI 工具最後回報的用量：沒勾第 5 項 → 提醒用的人按「繼續」；勾了 → VBear 自己按（和用的人按的「繼續」一樣：
     被打斷的那一步不重做，下一步會被告知上一步可能不完整，ADR 0006 第 8 點）。
   - 上限：每次暫停最多自己接續 1 次、每份派工 3 次、全部每天 5 次；自己接續後 10 分鐘內又因同樣原因暫停就不再自己接續；恢復時間在 12 小時以前就過了就只列出來。
   - 其他暫停原因（不確定有沒有送出、被中斷、回合出錯、員工在忙……）要人看過才能決定，不倒數、不自己接續。
   - 群組的一輪因每天上限暫停時只倒數、到時間提醒；不自己接續（ADR 0007 第 3 點：只有用的人說話才有員工回答）。例行工作只有一個回合，沒有可以接續的。

8. **紀錄不加欄位，「是誰決定的」照實寫。** 聊天、派工、群組紀錄的格式都不變（回到 v0.17.1 讀得懂）：例行工作的每一次記在 `<state>/routines/runs.jsonl`（`by: you|auto3`），
   自己接續在派工紀錄寫 `continued` by `vbear`、另在 `<state>/routines/auto-continue.jsonl` 記「第 5 項」。「AI 自己做了什麼」把它們寫成「自己動手第 3 項」「自己動手第 5 項」，
   可以停下正在跑的那次、停用例行工作。`config.json` 只有 `autonomy` 多兩個鍵（`routines`、`auto_continue`），只由設定頁的路由寫。

9. **三件永遠不准做的事與每次都問不因技能、例行工作、自己接續改變。** `vbear/skillbook*.py`、`vbear/routine*.py`、`vbear/auto_continue.py` 加進 `tests/test_autonomy_guard.py` 的掃描：
   不寫 `config.json`、不啟動終端機或完整模式或任何程式（`caffeinate` 只在 `keep_awake.py`，固定 argv）、不碰技能檔與技能的安裝、不建或改角色卡、不回覆允許卡；
   寫技能與例行工作的函式只在 `server.py` 的路由被呼叫；自己開始只看第 3 項、自己接續只看第 5 項（行為測試：沒勾時一次都不送）。第 4 項（不必每次問）這版照舊不能勾。

## 考慮過的其他選項

- **技能寫成 AI 工具的 `SKILL.md`（例如放進 `~/.claude/skills`）**：最像「技能」這個字，但會改到用的人自己的 AI 工具設定（他在終端機用時也會被載入），
  VBear 的安全模式聊天又不載入技能，Codex 聊天也關掉了；等於做了一個 VBear 自己用不到、卻改了別人設定的東西。不選。
- **技能插在角色卡上、每次聊天自動帶進系統指示**：員工會「自己知道」什麼時候用，但每個技能都變成每個聊天都送出的指示（和記憶同一類的持久提示注入路徑），
  改了也只有新聊天看得到（P42-6）；而且一張卡插很多技能時系統指示會很長。不選；只給某位員工的做法照舊寫在固定指示。
- **技能直接送出、不先放進輸入框**：少按一次，但用的人看不到這次送了什麼。不選。
- **照 GLOSSARY 字面「用的人啟用後，依排定時間重複交給員工」，不勾第 3 項也到時間自己做**：最方便，但那正是第 3 項「定時執行」的內容（ADR 0003），預設放開違反「AI 提議、你確認」。不選；GLOSSARY 改寫清楚。
- **每件例行工作重用同一個聊天**：聊天列表比較乾淨，但前文越來越長（每次越來越貴）、記憶與固定指示改了看不到（P42-6）。不選；每次新聊天。
- **VBear 關著也做（launchd 的 LaunchAgent、背景常駐、選單列 App）**：最像雲端服務，但在用的人電腦上多一個開機就跑、看不到視窗的程式，關掉 VBear 不等於停下 AI；
  也要改 App 的生命週期與打包。ADR 0003 Q6 已選「關著不做」。不選。
- **用 `pmset schedule wake` 到時間把 Mac 叫醒**：要管理員權限，而且是改系統設定。不選。
- **錯過幾次就補做幾次／錯過就跳過**：前者回來一打開可能花一堆錢、做一堆過時的事；後者 ADR 0003 Q6 不採用。選「只補最近一次」，自己補做再加 12 小時與 3 件的上限。
- **群組也自己接續**：等於 VBear 在用的人不在時開始新的一輪對話，違反 ADR 0007 第 3 點。不選。
- **派工的自己接續寫 `by: auto5` 在派工紀錄裡**：最直接，但 v0.17.1 的 `record_problem` 不認得，回到 v0.17.1 時整份派工會被當成損毀、隔離。不選；另記一個檔。
- **例行工作每次自己的花費上限**：最精準，但要改 daemon 的回合上限（`vbear/runtime/`），這版不碰啟動邊界。不選；用每回合上限＋例行工作每天上限。

## 後果

- 導覽多「技能」「例行工作」；聊天與群組的輸入框多「用技能」，每句話旁多「存成技能」，一對一聊天多「整理成技能」；每一頁上方多一行「等你決定」；
  設定頁自己動手第 3、5 項可以勾；派工頁、群組頁暫停時有倒數；「AI 自己做了什麼」多例行工作與自己接續。
- 新的紀錄：`<state>/skillbook/`（`skills.json`、`log.jsonl`、`suggest/ks-*.json`）、`<state>/routines/`（`routines.json`、`runs.jsonl`、`settings.json`、`heartbeat.json`、`auto-continue.jsonl`、`log.jsonl`）、`routine-runner.lock`。
- 新的對外資料路徑：整理成技能把聊天最近的對話送到 Anthropic（和整理要記住的事同一類，按之前寫明）。例行工作與技能本身沒有新的路徑：送出的是用的人的話，走原本的聊天。
- VBear 第一次在用的人電腦上啟動一個不是 AI 工具的程式（`caffeinate`），只在用的人打開開關時、只在有工作時；寫進 SECURITY-MODEL。
- `vbear/runtime/` 只多 `memory_rules.check_text`，啟動邊界沒有改。
- **已知缺口：聊天背景程序算「今天花了多少」時不含整理成技能的花費。** `vbear/runtime/daemon_chat.py` 的 `_chat_day_spent` 讀一份寫死的清單（幕僚長、記憶提議），
  不認得 `skill_suggest`；守門規則不允許 runtime 認得技能，這版也不改啟動邊界，所以不補。後果：聊天回合的每天額度檢查最多多給整理成技能已花的錢（每次最多 US$0.10，
  整理幾次就多幾次）。反方向沒有缺口：整理成技能自己「開始前」的檢查有算進聊天的花費，帳本（`GET /api/meetings/ledger`）的 `includes` 也列 `skill_suggest`。
  要補的話之後另開 ADR，讓 daemon 認得一個不帶技能內容的花費種類名稱。
- 殘餘風險（寫進 SECURITY-MODEL 新的「Skills and routines (v0.18)」）：
  - 存成技能的員工的話，之後用的時候變成用的人的指令；擋在中間的是存的時候的確認、用的時候放進輸入框讓人看，以及每個指令都要按允許。
  - 勾了第 3 項時，例行工作在用的人不在時開始；員工要動手的卡片沒人按就當作拒絕，所以不會不問就做事，但模型的回覆（例如一段文案）照樣會產生並花錢，在例行工作每天上限內。
  - 勾了第 5 項時，派工會在半夜自己繼續；被上限打斷的那一步不重做，下一步可能拿到不完整的回覆。
  - 例行工作的內容是用的人寫的，但員工被允許的指令可以讀到 VBear 的存取權杖並呼叫 VBear 的 API（和所有聊天相同）；你不在時沒有指令會被允許。
  - 時間靠 Mac 的時鐘；時鐘被改時，同一個時間不會做兩次，但可能被當成錯過。
- 回到 v0.17.1 時：技能與例行工作的資料夾留著、不被讀，例行工作不再執行、不補做；`caffeinate` 跟著 v0.18.0 的 console 結束；`autonomy` 多的兩個鍵不影響，
