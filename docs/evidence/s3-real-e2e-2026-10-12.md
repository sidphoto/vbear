# S3 real-model end-to-end evidence — 2026-10-12

The acceptance of the automatic mode (S3 design, section 10) with the real models: a real Claude Code executor
(Haiku, stream mode, full model id) and real Codex reviews, driven through the console's HTTP API by
[`tools/s3_real_e2e.py`](../../tools/s3_real_e2e.py). The only human acts played by the driver are the ones the
design allows: approve the plan and accept the risks (one preview, one confirmation) and start the executor.
Everything after that is VBear's own.

- Claude Code **2.1.296** (stream-verified for this run, see [claude-code-2.1.296-stream.md](claude-code-2.1.296-stream.md)),
  model `claude-haiku-4-5-20251001`; Codex **0.160.0**, model `gpt-6-luna` (high), a dedicated `CODEX_HOME`.
- A dedicated state directory (not the real `~/.vbear`), a temporary console port and the daemon socket inside that
  state directory. The toy repository is a small Python project created by the driver (a spec, a smoke test); its
  work is the executor's.
- Limits, set conservatively: at most 3 reviews, 6 dispatches, 100 review responses, 60 executor responses a turn,
  150 in total, executor budget USD 0.50, a 45-minute wall-clock cap enforced by the driver.
- Nothing was merged, pushed or tagged. The reviewer's account and the executor's account are named only by the
  product's own fingerprints in the preview, and no value of them is recorded anywhere here.

What each assertion list says (the driver fails a scenario if any is false):

- **full**: the loop ended at the merge gate; a NEEDS WORK came before the PASS; every review valid, complete and
  cleaned; one dispatch per review round; no dispatch id, review round or review job used twice; every
  `auto_*` event marked as the automation's own.
- **stop**: a review was running when the stop was pressed; the flow is held; the review's process was cleaned up
  (`cleaned`, nothing retained, no scratch directory left); the stopped review is not a valid review; nothing was
  dispatched or reviewed in the 90 seconds after the stop; the flow did not resume by itself; the same no-duplicates
  and marking assertions.
- **restart**: a review was running when the console was restarted; the runtime daemon kept running while the
  console was down; then the same as full: the review that was running finished and was judged, no dispatch or
  review was repeated, the loop ended at the merge gate with a PASS.

## What the runs before them found

The passing runs are the last of a series. Each failed run was stopped by the product (fail closed) or by a
driver assertion; none was repeated blindly. What each one found, and what was done:

| # | Found by | What | Done |
|---|---|---|---|
| 0 | the first step | the Mac's Claude Code (2.1.296, after Claude Code updated itself) was not stream-verified; the constants table and the administrator-source table had no entry, so the stream executor could not start at all | probe, constants, evidence ([claude-code-2.1.296-stream.md](claude-code-2.1.296-stream.md)); the screen names the cause but not the remedy: a follow-up |
| 1 | run 1 | `system/vcs_state_changed`, a new event after a `git commit`: unknown type, turn invalid. The probe's turns ran no git | known kind for 2.1.296 only; the probe has a third turn that commits and must see the event |
| 2 | run 1 | the model cannot know the dispatch id its report must carry (it is only the transport `uuid`); it invented one | the fixed report request appended to every dispatch text, naming the id and the report's fields |
| 3 | run 2 | a new `assistant` field in a longer turn; the journal only said "extra fields" | the journal now names unexpected fields (names only); the field is allowed for 2.1.296 |
| 4 | run 3 | `system/permission_denied` in the second turn: a refused tool call, unknown type, turn invalid | a known event, the turn stays valid; the tool name and decision type are journalled (filtered) and shown; what was refused could not be reproduced and is not recorded |
| 5 | run 4 | the executor honestly reported `tests: not_run` (the staged toy plan had no test to run) and the runner refused to send it to review: the gate working as designed | the toy repository has a smoke test; the plan says to run it |
| 6 | run 5 | the review prompt's "git clone … {workdir} repo" was read by Codex as one directory name (`toy repo`); VBear's strict check of the clone rightly judged the review invalid | the prompt names the source as one always-quoted argument and the destination as `./repo`; the reason names the directories found |
| 7 | the first stop run | a command the reviewer started as it was stopped was alive in a group of its own at the instant the group was proven empty; the review was kept for a person though the process ended moments later | a bounded, polled grace (10 s, 0.2 s) for observed descendants before manual review; no signal is sent; review and session end |

## What is not claimed

- Three runs of one small task prove the loop works with these models on this Mac, not that it works for every
  repository, model or Claude Code version. The refusal a real executor met in run 3 was not reproduced.
- The other scenarios of design section 10 (a daemon restart in a turn, a second console, a stop in a turn, a
  stop then continue, the interruptions at the action boundaries) are covered by the synthetic-CLI tests, not by
  these runs; the approval screen check is a separate hand check.
- The reviewer's verdicts are the model's; the runs show that VBear's checks of them (family, rollout, usage chain,
  report format, the reviewed commit, the clone's state) held, not that the verdicts were right.
